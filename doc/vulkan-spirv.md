# Vulkan Mock & SPIR-V Backend

## Overview

This module (`vulkan/`) handles two distinct tasks:

1. **Host side**: Insert Vulkan dispatch mock calls into the host IR for every kernel launch site
2. **Device side**: Convert device LLVM IR to SPIR-V binary (compute shader)

Both operate on our own IR tree — no external Vulkan or SPIR-V tools required.

## Host: Mock Function Generation

### The Runtime Library

The generated host IR calls into a companion C library `libcmpl-vk-runtime` (in `rt/`). This
separation keeps the generated IR clean and makes the mock system debuggable:

```
Generated Host IR              Runtime Library (linked at compile time)
─────────────────────          ─────────────────────────────────────
call @cmpl_vk_launch()  ──→    cmpl_vk_launch() {
                                  vk_lookup_or_create_pipeline()
                                  vk_bind_buffers()
                                  vk_record_dispatch()
                                  vk_submit()
                                }
```

### Runtime API

```c
/* rt/cmpl_vk_runtime.h */

/* one-time global init: creates VkInstance, VkDevice */
void cmpl_vk_init(void);
void cmpl_vk_shutdown(void);

/* register a SPIR-V kernel for later launch */
int  cmpl_vk_register_kernel(const char* name, const uint32_t* spirv, size_t size);

/* launch a kernel -- the core mock function */
void cmpl_vk_launch(const char*      kernel_name,
                    int gx, int gy, int gz,    /* grid dims */
                    int bx, int by, int bz,    /* block dims */
                    size_t shared_mem,          /* dynamic shared memory */
                    void*  stream,              /* NULL = default stream */
                    int    n_args,              /* number of args */
                    ...);                       /* variadic: kernel args */

/* synchronization */
void cmpl_vk_sync(void* stream);

/* memory management */
void* cmpl_vk_malloc(size_t size);
void  cmpl_vk_free(void* ptr);
void  cmpl_vk_memcpy(void* dst, const void* src, size_t size, int dir);
```

### Kernel Registration

At program startup (before `main`), all device kernels are registered with the runtime.
Each SPIR-V binary is embedded as a static array:

```c
/* auto-generated by the compiler */
static const uint32_t __spv_vec_add[] = {
    0x07230203, 0x00010000, 0x0008000b, 0x0000002e,
    // ... full SPIR-V binary
};

__attribute__((constructor))
static void __register_kernels(void) {
    cmpl_vk_init();
    cmpl_vk_register_kernel("vec_add", __spv_vec_add, sizeof(__spv_vec_add));
}
```

### Mock Insertion Pass

The mock generator (`vk_mock.c`) walks the host IR and transforms each `AST_KERNEL_LAUNCH`
site. The transformation happens at the IR level (not AST), replacing a placeholder call
with the actual `cmpl_vk_launch()` call.

```
Before (from IR gen of kernel launch):
  %call = call @__cmpl_kernel_placeholder(vec_add, {256, 128}, args...)

After (mock insertion):
  %call = call @cmpl_vk_launch(
      i8* getelementptr ([8 x i8], [8 x i8]* @.str_vec_add, i32 0, i32 0),
      i32 256, i32 1, i32 1,    ; grid: 256, 1, 1
      i32 128, i32 1, i32 1,    ; block: 128, 1, 1
      i32 0,                     ; shared_mem
      i8* null,                  ; stream
      i32 4,                     ; n_args
      float* %d_a,               ; arg 0
      float* %d_b,               ; arg 1
      float* %d_c,               ; arg 2
      i32 %n                     ; arg 3
  )
```

### Descriptor Set Layout

The runtime infers the Vulkan descriptor set layout from kernel parameter types:

| C Parameter Type | Vulkan Descriptor Type |
|---|---|
| `T*` (pointer) | `VK_DESCRIPTOR_TYPE_STORAGE_BUFFER` |
| `const T*` | `VK_DESCRIPTOR_TYPE_STORAGE_BUFFER` (read-only) |
| `int`, `float`, etc. (value types) | Push constant (or uniform buffer for >128 bytes) |

For each kernel, the layout is inferred: pointer args get binding indices 0, 1, 2...
Value args go into the push constant block (max 128 bytes by spec).

## Device: SPIR-V Emission

### SPIR-V Binary Format (Quick Primer)

A SPIR-V module is a stream of 32-bit words:

```
[Magic] [Version] [Generator] [Bound] [Schema]
  [Capability inst...]
  [Extension inst...]
  [ExtInstImport inst...]
  [MemoryModel]
  [EntryPoint inst...]
  [ExecutionMode inst...]
  [Debug inst...]
  [Annotation inst...]
  [Type/Const/Global declarations...]
  [Function definitions...]
```

Each instruction: `[WordCount | Opcode] [Operands...]`

### Emission Algorithm

The SPIR-V emitter (`vk_spirv.c`) walks the device IR module:

```
ir_module_to_spirv(IR_Module* mod) → uint32_t* binary, size_t len

1. Collect all types used in the module → assign SPIR-V type IDs
2. Declare capabilities: Shader, Int64, Float64, etc.
3. Emit MemoryModel: Logical, GLSL450
4. For each IR_FUNC with LINKAGE_KERNEL:
   a. Emit OpEntryPoint + OpExecutionMode (LocalSize = block dims)
5. Declare built-in variables: WorkgroupId, LocalInvocationId, etc.
6. For each global variable → OpVariable with storage class
7. For each function → OpFunction + blocks + instructions
```

### Type Mapping: LLVM IR → SPIR-V

| LLVM Type | SPIR-V Type |
|---|---|
| `void` | `OpTypeVoid` |
| `i1` | `OpTypeBool` |
| `i8` | `OpTypeInt 8 0` |
| `i16` | `OpTypeInt 16 0` |
| `i32` | `OpTypeInt 32 0` |
| `i64` | `OpTypeInt 64 0` |
| `f32` | `OpTypeFloat 32` |
| `f64` | `OpTypeFloat 64` |
| `ptr(addrspace=1)` | `OpTypePointer CrossWorkgroup` |
| `ptr(addrspace=2)` | `OpTypePointer Workgroup` |
| `ptr(addrspace=3)` | `OpTypePointer UniformConstant` |
| `ptr(addrspace=0)` | (error — no host pointers in SPIR-V) |
| `array` | `OpTypeArray` |
| `struct` | `OpTypeStruct` |
| `vector` | `OpTypeVector` |
| func type | `OpTypeFunction` |

| LLVM IR Instruction | SPIR-V Opcode |
|---|---|
| `add i32` | `OpIAdd` |

| `fadd` | `OpFAdd` |
| `sub / fsub` | `OpISub / OpFSub` |
| `mul / fmul` | `OpIMul / OpFMul` |
| `udiv / sdiv / fdiv` | `OpUDiv / OpSDiv / OpFDiv` |
| `and / or / xor` | `OpBitwiseAnd / OpBitwiseOr / OpBitwiseXor` |
| `shl / lshr / ashr` | `OpShiftLeftLogical / OpShiftRightLogical / OpShiftRightArithmetic` |
| `icmp eq/ne/slt/...` | `OpIEqual / OpINotEqual / OpSLessThan / ...` |
| `fcmp` | `OpFOrdEqual / OpFOrdNotEqual / ...` |
| `alloca` | `OpVariable` (in function scope, Function storage class) |
| `load` | `OpLoad` |
| `store` | `OpStore` |
| `call` | `OpFunctionCall` |
| `ret` | `OpReturn / OpReturnValue` |
| `br` | `OpBranch` |
| `cond_br` | `OpBranchConditional` |
| `phi` | (handled during SSA conversion — see below) |
| `select` | `OpSelect` |
| `bitcast` | `OpBitcast` |
| `gep` | `OpAccessChain` or `OpInBoundsAccessChain` |

### Built-in Variables

Device IR references to CUDA built-ins (`blockIdx.x`, etc.) are emitted as LLVM intrinsic
calls during IR gen. The SPIR-V backend recognizes these intrinsics and emits the
corresponding SPIR-V `OpVariable` with `BuiltIn` decoration:

```c
static const struct {
    const char* intrinsic;           // LLVM intrinsic name
    SpvBuiltIn builtin;              // SPIR-V built-in
} BUILTIN_MAP[] = {
    { "llvm.spirv.builtin.workgroup.id",       SpvBuiltInWorkgroupId },
    { "llvm.spirv.builtin.workgroup.size",     SpvBuiltInWorkgroupSize },
    { "llvm.spirv.builtin.local.thread.id",    SpvBuiltInLocalInvocationId },
    { "llvm.spirv.builtin.num.workgroups",     SpvBuiltInNumWorkgroups },
    { "llvm.spirv.builtin.local.thread.index", SpvBuiltInLocalInvocationIndex },
    { "llvm.spirv.builtin.subgroup.size",      SpvBuiltInSubgroupSize },
    { NULL, 0 },
};
```

The emitter pre-declares these as `OpVariable` with `Input` storage class and the
appropriate `BuiltIn` decoration, then replaces calls to these intrinsics with `OpLoad`.

### SPIR-V Binary Output

```c
typedef struct {
    uint32_t* words;
    int       len;
    int       cap;
    /* ID counter */
    int       next_id;
    /* type cache: IR_Type* → SPIR-V type ID */
    int       type_ids[256];
    int       n_types;
} SPIRV_Writer;
```

Functions:

```c
void     spv_init(SPIRV_Writer* w);
uint32_t spv_alloc_id(SPIRV_Writer* w);
void     spv_emit_header(SPIRV_Writer* w);
void     spv_emit_capabilities(SPIRV_Writer* w, IR_Module* mod);
void     spv_emit_types(SPIRV_Writer* w, IR_Module* mod);
void     spv_emit_function(SPIRV_Writer* w, IR_Func* func);
void     spv_emit_block(SPIRV_Writer* w, IR_Block* block);
void     spv_emit_inst(SPIRV_Writer* w, IR_Instr* inst);
uint32_t spv_type_id(SPIRV_Writer* w, IR_Type* type);
```

### SSA Handling for SPIR-V

SPIR-V uses SSA form natively. LLVM `phi` nodes must be lowered before SPIR-V emission
because SPIR-V's structured control flow doesn't have phi:

- During SPIR-V emission, `phi` nodes are lowered to `OpVariable` (Function storage class) +
  `OpLoad`/`OpStore` at predecessor/successor boundaries
- This is correct but less efficient — the mem2reg pass in the optimizer should eliminate
  most allocas and phis before SPIR-V emission

### Device IR Dump (for `-S` flag)

When `-S` is passed, the device IR is also dumped as `.ll` text before SPIR-V conversion.
This is done by `vk_spirv_dump.c` which calls the same `ir_dump()` function used for
host IR output.

## Descriptor Set & Pipeline Layout (`vk_layout.c`)

Before mock generation, the kernel signature is analyzed to produce a descriptor set layout:

```c
typedef struct {
    int binding;          // 0, 1, 2, ...
    int is_pointer;       // storage buffer vs push constant
    int is_readonly;      // const T* → read-only
    IR_Type* element_type; // the T in T*
    int     array_size;   // for arrays
} KernelParam;

typedef struct {
    String name;
    KernelParam* params;
    int n_params;
    int push_constant_size;  // total bytes of value params
    int grid_dims[3];        // from kernel launch config
    int block_dims[3];       // from kernel launch config (or default)
} KernelLayout;
```

This layout information is:
1. Embedded in the generated code as runtime registration metadata
2. Used by the runtime library to create VkDescriptorSetLayout and VkPipelineLayout

## File Layout

| File | Purpose |
|---|---|
| `vulkan.h` | Shared types: KernelParam, KernelLayout, SPIRV_Writer |
| `vk_mock.c` | Host IR pass: replace kernel placeholder calls with cmpl_vk_launch() |
| `vk_spirv.c` | Device IR → SPIR-V binary emission |
| `vk_spirv_dump.c` | Device IR → .ll text dump (for -S flag) |
| `vk_layout.c` | Kernel signature → descriptor set layout analysis |

### Runtime Library (in `rt/`)

| File | Purpose |
|---|---|
| `cmpl_vk_runtime.h` | Public API for generated code |
| `cmpl_vk_runtime.c` | Core: init, pipeline create/lookup, dispatch, sync |
| `cmpl_vk_utils.c` | Helpers: SPIR-V loader, buffer allocation, memory mapping |

The runtime library is NOT built by Cmpl — it's a separate library linked with the user's
compiled program.
